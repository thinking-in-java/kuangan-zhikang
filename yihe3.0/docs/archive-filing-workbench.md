# 档案填写工作台

入口：报告与档案中心 → 档案填写工作台，`/assets/report-center/filing.html`。复用系统顶部与左侧导航，不新增重复外壳。

## 页面及交互

按参考图布局实现六项办理统计、待办/进行中/已完成筛选、左侧职工任务与勾选批量操作、中间档案类型切换和四阶段流程、八类表单目录、右侧辅助填写与办理记录、底部草稿/校验/预览/下一步。

- 职业健康监护、普通健康数据两种档案独立保存，不互相覆盖。普通健康档案不要求不存在的职业类别或入职资料。
- 基础身份、单位、岗位、职业接触史及报告结果只读关联原资料。表单补录和处理说明保存为新版本，不改变职工姓名、性别、出生日期或报告原值。
- 一键填充先展示原文、报告与页码依据，仅带入当前为空且有来源的防护措施、明确 ISO 接触日期或职业史说明；不猜测入职日期、诊断、风险、接触等级。
- AI 仅在明确开始分析后调用已有 `/agent`，关联当前职工 ID。建议需再次点击才进入未审核说明，仍须显式保存。
- 三种模板改变填写重点和当前表单目录，支持下载空白 JSON 模板；八类目录可直接切换，三类资料支持增删，记录要求选择本职工来源原件。
- 保存草稿、提交职工确认、登记真实确认材料、医生审核、表单归档均新增版本并记录经办人及说明。再次保存重置后续确认。历史版本只读。原报告仍按既有审核归档机制处理，不能由表单归档替代。
- 页面刷新保留类型、筛选、页码和选中职工；历史版本可按参数恢复。未保存内容切换时提示。
- 完整预览、浏览器打印、JSON 导出覆盖基础信息、表单补录、检查结果、三类资料记录、报告来源及状态。原报告打开新标签，不丢失未保存草稿。
- 即将超期只依据人工填写的办理期限统计未来7天内任务；未设期限不推断超期。

## API / 数据

执行 `database/migrations/V018__a_filing_workbench.sql`：为现有监护版本表增加 pending_employee/archived 阶段，新建独立的 `a_general_archive_versions`，不修改职工或原始体检数据。当前业务库及隔离测试库已执行。

- `GET /ehr/api/report-center/filing`：档案任务及真实阶段统计，支持 kind/state/status/search/page/limit。
- `GET /ehr/api/report-center/filing/{recordId}?kind=...&version=...`：当前或历史快照。
- `GET /ehr/api/report-center/filing/{recordId}/fill-proposal?kind=...`：无写入的原文填充建议。
- `POST /ehr/api/report-center/filing/{recordId}/actions?kind=...`：save/submit/confirm/review/archive。
- `POST /ehr/api/report-center/filing/batch-fill`：1–20份未填写或草稿档案，保留版本与来源摘要，事务内全部成功或全部回滚，不推进确认与审核。

所有接口复用单位、数据模式和档案权限，个人端拒绝访问。写入要求原系统医生权限及同源/CSRF验证。档案类型白名单，不接受请求控制 SQL 表名；对版本冲突、重复条目、来源变化、幂等键复用作校验。每类档案独立版本链，审核和归档尊重候选环境限制。确认材料需核验并登记，不伪造职工数字签名。
