# 旧职工档案页面空列表修复

页面：`/manage/newpage/personalBasicInformation`；数据接口：`/newRegController/selectRegInfo`。旧表仍为 `new_reg`，与新建的 `a_` 健康档案模块分开；本次未修改旧档案数据。

修复前实测：未带筛选时接口返回20条记录；页面组织树初始化却自动选中集团根节点，并在100ms后以 `workUnit=甲由集团` 重新请求。旧档案的工作单位存储煤矿、电厂等具体名称，集团名称筛选结果为0，因此首次有数据的列表被第二次空结果覆盖。健管师默认选项还使用单个空格作为值，点击搜索时也可能被当成实际编码。

本次修改：

- 默认单位为“全部单位”，不自动把集团名称填成具体工作单位，不发送覆盖首屏的第二次初始化筛选。
- 集团根节点按全部单位处理，具体单位仍按用户选择查询。
- 默认健管师编码为空，兼容请求中的纯空格。
- 列表与总数复用同一 SQL 关联和筛选片段，保留原列表可见范围；原先列表返回20条而总数仅为6的情况得到修正。
- 建档时间筛选使用 `insert_date`，并校验时间范围；错误响应不再被前端当成正常的“无数据”。

12项只读回归已通过：无筛选列表、单位筛选、空格健管师、翻页、非法日期、建档日期、浏览器首次加载、默认空筛选、无集团自动筛选、浏览器单位搜索、清除恢复，以及无JavaScript异常。验证报告见 `database/legacy-archive-verification.json`。浏览器检查实际运行 Layui 原页面，未使用模拟数据。数据库实际 `new_reg` 为2311行；旧关联查询按原列表语义存在少量多行结果，返回总数表示列表查询条目数。
