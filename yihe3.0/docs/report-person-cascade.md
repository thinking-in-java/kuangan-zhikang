# 删除职工与体检报告清理

从 2026-11-17 起，`DELETE /ehr/api/records/{id}` 在原有权限、CSRF、rowVersion、原因及待处理更正申请校验后，同事务删除该职工的新健康档案模块体检报告。

- 包含报告所有版本、检查项目、原始证据、医生结论和建议、审核快照、归档发布、识别收据、任务及调度记录；移除依赖报告的风险结果和随访任务。
- 职工名册仍按原有方式停用，保留原系统身份，不修改旧系统 `yh_*` 表。
- 历史报告曾关联其他职工时拒绝整次操作，提示先核对关联，避免误删他人报告。
- 原件只有在没有其他报告引用时才删除；数据库事务提交后由持久化文件清理队列删除原件及该任务的模型缓存。失败自动重试，不先删文件再回滚数据库。
- 被删除任务的旧 Worker 回调返回 404，不能重新写回报告。
- 普通 SQL 对已审核数据的防删除保护继续有效；只有指定报告处于受控删除事务中才允许清理。
- `a_report_deletions` 仅记录报告 UUID、范围、操作者、原因和删除数量，不保存报告正文；`a_report_file_cleanup_tasks` 记录文件清理状态。

当前单份报告的“× 移除”仍沿用未审核报告解除关联接口，与删除职工时的联动清理职责不同。

本地全部清理脚本为 `database/clear_all_exam_reports.py --all`，仅供受控维护使用；执行前停止上传服务和识别适配器。清理只针对新 EHR 表，保留职工、名册、小程序账号和微信绑定。脚本会清除旧完整度快照并按保留的基础资料重新计算。

验证：`tests/ehr/test-report-cascade.py`（隔离 synthetic 环境，包含已审核报告、事务回滚、范围隔离、原件/缓存清理、旧任务阻断、同原件重新上传）。
