# 评估规则管理

入口：健康评估中心 → 评估规则管理。页面 `/assets/assessment/assessment-rules.html`，复用现有平台菜单、矿井横幅和蓝白面板，以用户参考图为布局依据；六个统计卡、八类标签、筛选表格、分页及右侧详情均已实现。窄屏下表格和标签横向滚动，详情移到下方。

## 功能与状态

- 规则类别：指标参考范围、单位转换、性别年龄范围、风险分层、职业健康、问卷计分、AI提示词；版本标签汇总各类规则并提供历史查看。
- 新增/编辑每次生成新草稿。保存草稿不会覆盖已发布内容；发布、启用须核对来源、适用人群及边界，并填写原因。停用保留历史。复制生成独立草稿，恢复历史版本也先生成草稿。
- 支持关键词、人群、分类和状态筛选，分页跳转，JSON导出、批量导入（1–100条、前端限制2 MB）。导入全批校验，只生成草稿。
- 试算校验数值边界、明确单位的线性转换、分层区间、接触关键词及配置分值汇总，不写健康档案、不访问模型、不自动确认风险。单位不符、缺少适用年龄/性别时不套用。区间不允许重叠。
- 当前单位授权医生可管理，移动端禁止；所有读取按单位和数据模式隔离。写入沿用CSRF、事务、乐观版本与请求幂等，操作留痕。

## 与已有评估的关系

`AssessmentRuleRuntime` 仅提取当前单位、当前模式、已发布且启用并适用于对应模块的规则，形成版本化上下文。AI体检评估、综合健康、职业健康、慢病、心理评估及新问卷草稿均读取此上下文。没有生效规则时保持旧版摘要算法兼容。

规则发布/启停会改变后续评估来源摘要；原任务发现来源变化须重新评估，不能直接审核过期任务。已发布问卷保持原始冻结版本；新发布问卷须保存当前规则快照。原始报告值、单位、参考范围、已有医生审核及权限流程不被配置改写。

统一规则作为辅助分析上下文，不是任意代码执行器，也不替代各业务模块既有审核/评分引擎。问卷只允许现有 `choice_sum_v1` 配置分值汇总，专业审核不可关闭。没有将截图阈值自动导入为已验证临床规则；当前真实规则库为空，需按实际依据创建并核对发布。

## 代码与数据库

- 页面与交互：`yihe-admin/src/main/resources/static/assets/assessment/assessment-rules.{html,css,js}`。
- 菜单：`yihe-admin/src/main/resources/templates/index.html`。
- API：`AssessmentRuleController`，服务 `AssessmentRuleService`，评估上下文 `AssessmentRuleRuntime`，均在 `yihe-framework/src/main/java/com/yihe/framework/ehr/`。
- 数据迁移：`database/migrations/V025__a_assessment_rule_registry.sql`，包含规则头、不可变内容版本、事件、幂等回执和发布互斥表。已应用于本地运行库与预览库；未加入临床规则或更改原健康数据。
- API根 `/ehr/api/assessment/rules`：GET列表，POST保存；GET `/{id}?revision=`详情；POST `/{id}/actions` 发布/启停/复制/恢复；POST `/import`；POST `/simulate`。
