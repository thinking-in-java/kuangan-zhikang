# OCR 识别工作台

管理平台入口：报告与档案中心 → OCR 识别工作台。独立页面 `/assets/report-center/ocr.html?report={reportId}&revision={revision}`，没有指定报告时打开当前范围最新报告；点击文件名或顶部统计卡片可切换报告。报告上传中心的“核对”操作直接进入工作台。

## 页面与原件

按参考图实现顶部八项统计、档案小谷状态、左侧缩略图与原件、右侧识别结果/字段修改记录/识别日志、底部操作栏。沿用系统外部导航，不增加重复侧栏。工作台激活时隐藏会覆盖底部按钮的健康师悬浮窗，其他页面正常保留。

PDF.js 4.10.38 在本地提供 PDF 预览、按需缩略图、翻页、适宽、缩放与旋转；本地第三方文件包含 Apache-2.0 许可证与 NPM 完整性摘要。预览读取现有鉴权下载接口，PDF 解析禁用动态求值；没有将原件发往外部预览服务。图片原件使用本地 Blob 预览。检查项目可点击定位证据页。

八项统计查询报告中心接口，不填写参考图演示人数。识别完成属于累计指标。服务状态只显示“服务已配置/未启用”，配置存在不冒充处理进程正在运行。

置信度尚无后端数据，整体显示“未提供”，各项显示“—”。标准化值只读取 `a_health_items.result_normalized`，缺少时显示“—”，不把原始值复制成标准化结果或自行换算。异常状态读取原文标记，空标记显示“未标记”，不默认等于正常。

## 接口与保存

- `GET /ehr/api/report-center/ocr/{id}/{revision}`：现有鉴权与单位/数据模式校验后读取报告、有限职工参考字段、原始审核记录、规范化值、该版本操作记录与真实 OCR 任务/尝试日志。个人端禁止使用。
- `PUT /ehr/api/report-center/ocr/{id}/{revision}`：需要 CSRF 和 `If-Match`。原有候选保存服务继续负责锁、当前版本、证据页码、检查项目、完整结论及审核限制。新接口同事务补录报告性别、年龄、工号、部门/班组和岗位的人工证据，并记录字段前后值。它不会更新 `a_employee_roster_profiles`。已审核、驳回或归档版本不能覆盖。
- 原件未识别到的报告信息保持空白；工号输入框可以显示关联档案工号作为占位参考，未经人工确认不写成报告事实。
- 保存修改不会审核或归档。提交匹配按钮要求人工确认报告与职工身份，在必要时先保存，再调用原有 `submit` 流程提交人工审核；未另造匹配结果。
- 重新识别要求明确确认，使用已有 OCR 入队接口。已审核版本需先通过原有修订流程建立新版本。
- 字段修改记录只显示可追溯的前后值；旧事件没有字段差异时不补造历史。无 OCR 队列任务的手工/批量导入报告明确显示没有 OCR 任务。

## 验证

`tests/ehr/java/OcrWorkbenchChecks.java` 仅允许 `shayu_3_preview` 隔离库，全部写入事务回滚。19 项检查覆盖读取、保存、元数据和指标、职工资料不变、差异留痕、版本冲突、参数校验、单位隔离、个人端拒绝、已审核只读、无自动审批/归档和无模型请求。

浏览器检查覆盖真实 PDF 像素渲染、缩略图、翻页、缩放旋转、字段编辑、未保存提示、409 冲突保留修改、保存请求内容、提交/重识别确认、URL 刷新、菜单，以及 1920/1366/390 宽度。浏览器的保存请求在测试中拦截返回冲突，不向业务库写测试修改。对照部署前后快照，职工、报告、账号及员工配置不变。
