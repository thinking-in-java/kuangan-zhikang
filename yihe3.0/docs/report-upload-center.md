# 报告与档案中心

入口位于管理平台左侧“健康驾驶舱”下方，页面为 `/assets/report-center/index.html`。保留原有健康档案及数字员工菜单。

## 数据和权限

`GET /ehr/api/report-center` 返回当前单位、当前数据模式下，未删除职工关联报告的当前版本。接口使用现有 `EhrAccess.web` 鉴权，禁止个人端访问。筛选参数包括 `page`、`limit`、`status`、`search`、`from`、`to`、`organization`、`channel`；日期按报告级体检日期筛选，搜索按姓名、工号及文件名匹配。

`counts` 随日期、单位、来源、搜索条件变化，独立于状态标签；`all` 是报告份数，不是职工数。识别完成是累计指标，包括待核对、待审核、审核通过和已归档，不能与这些细分状态相加。环图使用互斥状态。当前报告必须关联已有职工，因此待匹配数量为零；不虚构未关联报告队列。

## 操作

- 单份、批量、拖拽上传均调用已有 `POST /ehr/api/records/{id}/reports`，逐份指定所属职工。保持现有 20MB、PDF/JPG/PNG 限制；BMP/Word 显示待接入。批量每批最多 50 份，逐份保存，单份失败时保留已成功上传结果，使用幂等键防止重试重复上传。
- 上传后由现有 OCR 队列处理。任务中心查询现有队列，页面每 15 秒刷新，弹窗打开时停止自动刷新。
- 报告查看从现有详情 API 读取检查项目。核对入口打开原有档案详情和编辑流程，不另建审核系统。
- 多份报告入口按职工汇总历次报告，保留独立原件，不提供文件物理合并或覆盖正式报告。
- 批量识别、审核、归档及移除沿用原接口、CSRF 校验、版本校验、权限与审核机制。审核与归档必须显式确认；不自动审批。部分逐份操作失败时提示刷新核对，不承诺跨接口原子事务。
- 状态、筛选和分页保存在当前页面 URL 中，刷新保持。
