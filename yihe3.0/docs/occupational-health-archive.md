# 职业健康监护档案

入口：报告与档案中心 → 职业健康监护档案。路由 `/assets/report-center/occupational.html?record=<recordId>`。保留原系统外壳，不增加重复边栏。

## 页面

按参考图实现顶部九项操作、职工横向信息条、九项档案目录、五个统计卡及八类资料总览：个人信息、职业危害资料、健康检查及处理、疾病诊疗、异常及风险、应急调离、职业病与伤残鉴定、历史检查资料。目录与查看详情均可进入相应资料区。

职工姓名按钮可打开职工选择器，支持姓名/工号/班组搜索与分页；与职工健康档案互相跳转并保留职工身份。姓名、出生日期、单位、班组、岗位及接触史读取原档案，不由监护表单覆盖。

职业资料优先读取关联报告 `a_occupational_profiles`，保留原字段、原文、页码、审核状态及原件入口。职业健康检查计数依据报告文件名或原结论的职业健康标识；其他报告标注类型待核定。异常项按报告原始标记计数；风险只读取已确认评估，不根据数量生成等级。缺失诊疗、事件和鉴定资料保留空状态。

模板管理提供标准、职业接触、检查处理三种填写重点，改变字段顺序并保存模板选择，支持下载空白 JSON 模板。表单支持新增/删除三类资料记录，每条要求关联当前职工原件。打印使用浏览器打印；导出 JSON 包含当前授权资料、来源和版本信息。原件可按文件选择下载，检查结果可进入 OCR 工作台对照原件。

AI 仅在明确点击开始后调用现有 `/agent`，关联当前 recordId；结果需用户选择才带入未审核说明，仍须显式保存。不会自动提交、登记确认或审核。

## 数据接口和版本

部署前执行 `database/migrations/V017__a_occupational_archive_versions.sql`。只增加一个表，不改动原始报告、职工表或现有审核表。当前本地业务库及隔离测试库已执行。

- `GET /ehr/api/report-center/occupational/{id}?version=N`：授权数据、监护表单、版本及来源摘要。历史版本使用保存时快照；最新版本读实时关联资料，来源变化显示提示。
- `POST /ehr/api/report-center/occupational/{id}/actions`：`save`、`confirm`、`review`。
- 所有读取校验当前单位、数据域、未删除职工，个人端不开放此企业接口；写入要求现有医生权限、同源与 CSRF 校验。
- 每次动作新增版本；原件、职工资料和旧版本不覆盖。保存新的表单重置为待确认。历史版本只读。
- `expectedRevision` 乐观版本校验；同一档案与来源行在事务内锁定。来源摘要变化拒绝陈旧提交。幂等键及载荷摘要阻止重复保存和键重用。
- 职工确认是登记已取得的本人确认材料，必须选择本职工原件、勾选真实材料核验并填写说明，不伪造职工数字签名。
- 医生审核要求先登记确认材料，核对身份与原件、填写监护类别，并确保关联报告已通过原系统审核；候选环境禁止确认。此操作只审核监护表单，不自动发布或归档原报告。
- 每次动作写入原档案审计日志，记录经办账号与说明。诊疗、鉴定或应急事项仅作为有来源的补录资料，不自动改变临床诊断或通知职工。

## 验证

Java 8 编译通过；26 项隔离数据库检查采用事务回滚，覆盖单位/模式/个人端权限、医生写入权限、表单来源、幂等、旧版本冲突、来源变化、确认与审核前置条件、候选环境、历史快照及审计，不修改原始职工与报告数据。测试：`tests/ehr/java/OccupationalArchiveChecks.java`。

Chrome 检查覆盖八块总览、九项目录、表单及记录增删、模板选择与下载、确认/审核交互、历史只读、职工切换、双向关联、打印导出、AI 显式触发、菜单集成和 1920/1366/390 像素适配。保存、确认和审核请求在浏览器验证中拦截；实际流程仅在隔离库测试并回滚，不创建业务监护档案或调用真实模型。

待有真实业务资料后，由授权人员补充入职时间、监护类别、防护措施、诊疗/鉴定及应急记录并核验其原件。当前不从不明权限的旧诊疗表猜测关联关系。
