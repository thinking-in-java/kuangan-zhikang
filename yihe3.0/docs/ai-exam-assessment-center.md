# AI 体检评估中心

入口：健康评估中心 → AI体检评估。页面 `/assets/assessment/exam.html`。在原授权健康评估分组中增加入口，保留既有子菜单与数字健康师。原系统顶部及侧边栏继续使用。

## 页面

按参考图实现矿山横幅、五项统计、姓名/工号/报告ID与日期/风险/AI/审核/单位/岗位筛选、当前版本报告列表、风险环图、近7日趋势、评估引擎状态、批次记录与最近任务。支持分页、字段显隐、CSV导出、单人/批量评估、重评、医生审核、退回、发布及取消。单份及批次可下载独立HTML评估报告。

所有统计读取实际数据。初始904份当前报告、尚无此中心的评估任务时显示待评估，不复制参考图示例数值。未评估/未审核不归为低风险。风险图只统计当前报告最新评估中医生确认的等级；高风险人数按高风险及极高风险结果关联职工去重，报告数与人数明确区分。趋势统计实际AI完成次数，平均耗时只取已完成任务，不展示虚构耗时。

## AI、审核及发布

- 复用既有 `DigitalWorkerModelClient` 独立服务配置，不更改OCR模型与OCR8报告并发；前端不返回模型名称、密钥或地址。
- 每份任务固定 reportId/revision/recordId，保存授权职工、指定报告、最多3份关联历史报告的结构化原文和出处快照、来源摘要。只根据这些数据生成待医生核对的分析，不声称已直接阅读PDF图像。
- 一次选择1–20份，遵守评估小谷接单、AI开关、任务类型和活跃上限配置。仅用户明确确认后创建任务并触发模型，初始页面不执行评估。
- 独立轮询线程与2个模型处理线程，使用PostConstruct启动，不依赖全局@EnableScheduling，也不阻塞既有OCR任务。持久化排队、租约、运行、失败、取消及完成状态。
- 处理前后重验当前医生授权、档案归属、报告当前版本与来源摘要。授权撤销、版本变化或来源修改时不写入旧模型结果；取消后晚到结果丢弃；租约过期结束为失败并允许用户重评，保留旧任务。
- 模型不自动赋风险等级和分数。医生必须完成身份与原件核对、填写审核依据并选择等级；要求原报告已经走原流程审核归档。确认写入现有 `a_health_risk_assessments`（分数NULL）和 `a_health_risk_report_sources`，引用已发布报告版本，沿用数据库权限与外键约束。
- 只有医生已审核结果可明确发布；发布记录与原报告分离，不修改原报告、不发送通知、不自动执行干预。批量发布任一版本/来源/状态不满足则事务整批回滚。
- 历史评估、来源快照、审核与发布意见保留。新评估不覆盖旧结果，已发布结果不能就地改写。

## 接口和迁移

执行 `database/migrations/V019__a_ai_exam_assessment.sql`，新增批次、任务、事件三表，不改写原有报告或职工。当前业务库、隔离测试库已执行。

- GET `/ehr/api/assessment/exam`：列表、筛选统计、风险分布、趋势、今日批次、引擎状态与最近任务。
- GET `/ehr/api/assessment/exam/{reportId}/{revision}?task=...`：当前或某次历史评估、原文出处与办理记录。
- POST `/ehr/api/assessment/exam/batches`：单人或批量队列请求。
- POST `/ehr/api/assessment/exam/tasks/{id}/actions`：review/reject/publish/cancel。
- POST `/ehr/api/assessment/exam/publish-batch`：批量发布已审核结果。
- POST `/ehr/api/assessment/exam/batches/{id}/cancel`：取消仍排队/运行的任务。
- GET `/ehr/api/assessment/exam/batches/{id}/detail`：按当前访问权限读取批次报告内容；已无授权或原件归属变化的结果不导出。

所有接口校验单位、数据域、未删除档案与原始报告归属；个人端拒绝，写入要求现有医生权限和同源/CSRF。写入使用任务版本、载荷摘要和幂等键。配置可用与队列心跳分开显示，均不冒充上游接口健康检查。用户输入筛选期间暂停自动刷新。
