# 体检报告自动入档流水线

本流程区分行政入档与医疗签署。行政入档记录在 `a_report_archive_entries`；医生签署及正式发布仍使用原有 `a_review_records`、`a_report_publications`，自动任务不写这两类确认记录。

## 正常路径

上传自动建档案小谷任务 → 原件保存及 OCR → 姓名、性别一致，且完整身份证号或完整手机号唯一匹配→ 校验出处、原件摘要、页码、日期、重复报告和指标质量 → 自动保存入档快照 → 评估小谷分析可信指标 → 医生按需处理医疗异常及签署评估。

工号、部门、岗位沿用基础资料，不要求报告提供。姓名加完整手机号唯一匹配时，出生日期等补充字段差异不阻塞匹配，也不覆盖花名册。原件依据不足或匹配多人时不自动关联；已关联另一职工时保留原来的医生改绑权限。

## 三类结果

- `auto_archived`：原报告、结构化指标、出处和入档版本已保存；医疗审核独立显示“未签署”。不需要逐份点击审核归档。
- `partial_archived`：原报告及可信指标已入档。不确定字段、缺失完整结论、部分页无提取内容等形成异常子任务，不阻塞已可信数据。评估输入排除待核验指标；不把“没有异常标记”当作正常。
- `needs_identity`／`needs_materials`／`blocked`：身份不明、日期不可确定、疑似重复、原件不可用或识别失败等需要核验。未确定身份的原件保留在待关联报告库；疑似重复不重复入档。

## 质量依据

采用 `archive-quality-v5-paragraphs`：姓名匹配、来源文件、日期、指标名、原始结果、证据页码和重复报告等业务规则通过后直接入档。置信度是识别服务的可选技术元数据，不是报告内容；缺少或低置信度都不作为自动入档的单独阻断条件，也不因此强制二次模型复核。定性结果直接保存；报告未提供单位或参考范围时保留为空，不虚构、不转成数值或正常判定。只有结果缺失、原文片段不一致、同页同名项目存在不同原值等实际数据问题才生成字段异常。跨页同名项目允许保留分项和摘要，已有原件复核通过的记录不因同名重复再次拦截。原件二次复核仅用于这些实际例外，不再要求所有扫描结果重新读一遍。

资料完整度、原文页覆盖率、可信指标数量、医疗审核状态分别展示。页覆盖率不表示 OCR 必然正确或临床健康。

## 下游与异常

行政入档与评估调用分别处理。模型未配置、关闭或队列满时，原件和入档快照继续保存，下游显示待服务并自动重试；不会把服务失败写成完成。自动评估使用 `archive-xiaogu` 系统身份，验证发起人的当前单位授权，不冒充医生。按来源及质量快照建立幂等批次，数据变化会取消旧快照的自动评估并排入新任务。评估结果保持待医疗审核，不自动诊断、开药、发送干预或签署风险等级。

原报告的 `HH`／`LL`／“危急”标记产生优先医疗提醒。不额外发明危急值阈值，也不直接发送外部消息。确认接收只记录接收人；医疗人员可另行记录异常处置依据。该记录不替代整份报告签署；同一异常观测值变化后提醒重新打开。

异常工作台默认展示有未处理问题的报告，支持字段定位、重新检查、接收及医疗处置记录。实际更正数据后质量异常自动消除，不能单击忽略就伪造数据质量通过。老报告可切到“全部”，按页批量启动历史报告整理；不会在部署时擅自批量签署已有报告。

## 数据及验证

迁移 `V027__a_report_auto_archive.sql` 新建入档当前状态、不可覆盖的行政入档快照版本和异常任务三张表，不修改花名册及已有医疗签署记录。行政版本与报告修订版本分开记录。医疗状态从真实签署记录对应的报告状态读取，避免两个状态失去同步。

`AutoArchivePipelineChecks` 在隔离预览库通过真实 MySQL 验证入档、可信指标过滤、自动评估队列、权限、幂等、异常消除、模型不可用及医疗提醒。模型使用测试替身，无外部医疗请求，数据全部回滚。浏览器测试 `test-auto-archive-review.cjs` 拦截业务 API，验证异常优先、状态分离及主要操作；上线后另行做真实账号只读检查。

扫描件在原件及初次提取完成后进入独立的原件复核队列 _archive_original_checks（迁移 V028），沿用数字员工模型及原件读取器。两条批处理线程对指定来源页再次提取并比较项目名、原值、单位、范围和异常标记；结果属于模型原件交叉核验，不代表医疗确认，也不伪造 OCR 置信度。输入快照、文件标记或原件摘要变化后失效。复核不持有档案数据库长事务，失败保留原件并重试；岗位关闭时不调用模型。

文字段落校验会读取项目全部证据引用，兼容换行和全半角标点。完整结果以足够长的原文片段开头、而证据仅是节选时，记录 excerptItems 并保留原文节选，不把缺少全文误报成矛盾，也不声称全文已核实；文字中的否定变化、数字不同及过短通用片段仍不会被当作全文匹配。

文字结果证据节选：保留完整识别结果和原件出处。证据为完整首句且至少含6个汉字时（如“脾脏大小正常”），按节选记录，不误判为文字矛盾；不完整短前缀、否定词差异和数值差异仍核验。节选不等同于整段文字已逐字核实。
