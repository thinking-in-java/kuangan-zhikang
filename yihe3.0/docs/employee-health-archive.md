# 职工健康档案

入口：报告与档案中心 → 职工健康档案，`/assets/report-center/employees.html`。

按提供截图的三栏工作台实现。左栏提供姓名、工号、班组检索，单位和风险筛选，分页及页码跳转；中栏包含职工信息、九个标签、六类指标、历史趋势、报告与异常记录及评估摘要；右栏提供完整度、预警线索、干预随访、心理及职业健康资料入口、AI 分析。

## 数据与权限

- `GET /ehr/api/report-center/employees`：复用现有档案检索和单位/数据域权限。
- `GET /ehr/api/report-center/employees/overview`：在档人数、已有报告人数、已确认高风险与极高风险、本月当前报告版本及未完成随访任务。
- `GET /ehr/api/report-center/employees/{id}`：授权档案、关联原始报告结果、已确认评估、随访及数字员工任务。所有查询均限定单位和数据模式；删除档案不参与统计；个人端拒绝企业接口。
- 已建档按“已有报告的职工人数”计，与已归档报告明确区分。无已确认风险评估显示未评估。
- 指标保留原始结果、单位、参考范围、异常标记与页码，可进入 OCR 工作台核对原件。不根据数值擅自新增临床判断；未知标记保持中性。
- 趋势只比较同名、同单位、带明确日期且可解析为数值的原始结果，最多最近六次。单次记录不补造趋势。血压原文的收缩压/舒张压分列呈现；未核定日期标为候选。
- 心理评估未接入时显示实际空状态，不把心理服务任务称为诊断或已确认评估。
- 干预、随访、评估、关怀通过现有 `/digital-worker-tasks` 创建待处理任务，使用现有 CSRF、医生权限、配置规则及幂等键；不自动发送通知、改变临床资料或执行干预。
- AI 仅在用户明确开始生成时调用现有 `/agent`，使用当前档案 ID；分析显示在独立结果区，不能自动应用动作。
- 查看完整档案通过受限同源 returnTo 返回，保留列表页码、筛选与选中职工。保留原健康档案模块与其他报告中心页面。

## 验证

Java 8 编译及 18 项隔离数据库检查（事务回滚）：跨单位/数据域与个人端权限、真实计数、不捏造随访评估、原始报告读取、搜索注入、读取不修改资料。浏览器检查涵盖 898 人、九个标签、六类指标、菜单集成、分页跳转、完整档案返回、派活请求和 AI 显式触发、1920/1366/390 像素宽度。浏览器写入操作拦截，未创建实际任务或调用实际模型。
