## 数据边界与口径

本版本为可操作前端原型，不是生产后端。`store.js` 使用独立键 `kuangan.archive.demo.v1` 在当前浏览器 localStorage 中保存合成演示记录，不调用业务写入接口、不修改真实数据库。所有页面均标注本地演示。不要录入真实敏感资料。

初始化 2,436 份虚构档案，其中已完善归档 2,243、待完善 126、待审核 67、审核通过待归档 0；高/中/低风险分别为 57/152/2,227。16个命名示例用于展示，其余使用“示例职工”编号。核心计数由同一记录集合计算，审核通过尚未归档时不计入完整档案。完整归档率按 2,243 / 2,436 四舍五入到一位小数为 92.1%，不再使用另一套 1,952 / 68 口径。

个人页报告与指标读取相同档案记录；统计页的总量、完整归档率、风险、来源、待处理数和CSV读取相同数据源。跨标签页保存后会更新；后续打开页面读取最近保存值。单位覆盖率、年龄/工龄与职业暴露/异常排行中尚未完成真实聚合的部分保留明确的示例标记或示例图表，正式上线必须由服务端按统一分母计算。

## 可操作流程

1. 新增、编辑、导入后进入待完善。工号不能重复，编辑已审核/已归档内容会撤回待完善并保留原日志。
2. 报告来源区分小程序上传、拍照上传、人工录入、历史档案导入。小程序同步未配置时仅提示，不生成伪同步结果。
3. 图片/PDF选择后登记材料，≤20 MB，保持“待识别”，不模拟 OCR 成功。手机拍照入口使用原生文件选择器的 `capture` 提示。
4. 可人工补录指标名称、数值和单位，明确标注人工补录。核对身份/职业字段、报告、结构化指标与异常数据后方可提交审核。
5. 人工审核可通过或填写原因退回。审核通过后还须单独归档；禁止跳过状态直接归档。批量操作要求所有所选记录状态一致，并弹窗确认。
6. 修改、补录、确认、提交、审核、归档和撤回均记录时间、演示处理人、操作及说明。仅待完善档案可软删除，删除原因必填。
7. CSV导入先预览校验，再确认写入本地；支持1–500条。任一工号重复或必填项错误则整批不导入。CSV导出支持当前筛选结果或所选条目，并处理公式起始字符。

附件正文仅存在当前详情页面内存中，刷新后不可重新下载，界面明确提示需重新选择原件；附件元信息、结构化指标、记录和日志会保存到本地。真实文件持久化、OCR、AI、人员匹配、细粒度权限、操作人认证与不可篡改审计尚未接入，不能将本地流程当作生产归档系统。
