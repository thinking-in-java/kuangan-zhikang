# 数字员工原件核对

`archive_completion` 任务现使用报告原件与实际录入项目比对，不再把完整度摘要作为核对结论。其他任务继续使用既有处理流程。

## 核对过程

1. 沿用登录、医生权限、机构范围、任务版本和 CSRF 校验。按任务明确关联的职工读取选定报告版本，不根据标题姓名猜测职工。
2. 通过现有档案文件服务读取原件。检查文件 SHA-256、页数、格式和路径范围；原件不存在或指纹不符时明确阻止核对，不根据登记数量生成通过结果。
3. PyMuPDF 逐页读取原生 PDF 文字；无有效原生文字的页渲染给数字员工独立模型识别。原生文字中的手机和证件号码会隐藏。扫描图像保留原件内容，仅供当前授权任务处理。
4. 对有明确项目名、结果和全部已填写列的原文行先做逐字匹配；数字边界不允许把 8.2 误匹配到 18.2，不做单位换算。其他项目按20条一批、最多两批并行，调用现有 OCR API 配置比对。
5. 模型引用必须在对应原件页真实存在，结果及相关列必须有原文支撑。扫描识别及不能证明定位的结果列为无法核实。长段结论或建议不能只凭一个片段就断言整段错误。
6. 分开展示原文一致、内容差异、格式差异、无法核实，以及去重后的疑似漏录。名称不同不直接认定漏录；连接符等印刷差异不算内容错误。
7. 保存原件指纹、报告版本摘要、逐项值、引用页码和时间。报告内容变化后旧结果不能审核通过；不完整或原件不可读的记录也不能审核通过。审核要求明确确认已按原件复核。

模型服务失败的批次列为未核实，不会计入一致。原件和报告指纹不变、前次模型批次完整返回时，可以重新读取原件、重新校验已有引用后复用比对记录，页面在核对范围中明确说明。

核对只生成任务结果，不自动修改健康档案、发送通知或形成临床处置。已完成的历史任务不覆盖；可创建新的原件复核任务。

## 界面与接口

- 任务详情主区优先展示结果和筛选表，任务信息、档案完整度和历史记录折叠显示。
- 未核实的识别值只作为候选值展示，不能冒充原件确认值。
- `POST /ehr/api/digital-worker-tasks/{id}/generate`：发起处理；档案核对允许待审核任务重新核对。
- `GET /ehr/api/digital-worker-tasks/{id}/originals/{sourceId}`：授权的 PDF / 图片内联预览，仅允许当前任务关联职工的原件。
- `POST /ehr/api/digital-worker-tasks/{id}/actions`：审核核对结果时需要 `originalReviewed: true`；仍校验报告摘要与任务版本。

## 部署

- 先应用 V013，在 `a_digital_worker_ai_attempts` 增加 `verification_json`。
- Python 依赖 PyMuPDF。当前使用本机已验证的1.28.2运行库，保存在 `.git/runtime/python-libs`，未写入前端。
- 配置 `ehr.digital-worker.pdf-python`、`ehr.digital-worker.pdf-python-path` 和 `ehr.digital-worker.original-script`。默认脚本为 `scripts/digital_worker_original.py`。
- 模型参数沿用 `ehr.digital-worker.model-config-file` 指向的数字员工专用配置，密钥只在后端读取。
- 当前运行包为 `.git/runtime/kuangan-integrated-97f7fd3-original-final.war`，启动脚本为 `.git/start-author-8080.ps1`。

## 本次验证

找到并恢复了与数据库指纹一致的解小敏11页原件，没有改动报告内容。新复核任务核对119条档案记录：56条原文一致、0条已证实内容差异、1条格式差异、62条不能自动证实；另有10条名称未匹配记录，单列为疑似漏录，不计为确定错误。历史已完成任务保留。

验证通过：37项后台智能体、45项个人智能体、23项派活及审核约束、16项原文证据、6项文件读取检查，共127项。桌面与窄屏浏览器检查涵盖结果筛选、原件预览及指纹、越权原件拒绝、审核确认和布局；测试没有自动审核真实任务或修改健康档案。

原生 PDF 的分栏、项目别名、跨页长文本及扫描页仍可能无法自动确认；这些项目明确留给人工核验，不宣称整份报告已全部通过。
