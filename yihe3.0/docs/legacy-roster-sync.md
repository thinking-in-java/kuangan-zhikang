# 旧职工基础资料同步

来源 `new_reg`；接收当前企业 `org:10000` 的 `real` 档案池。只同步该企业现有组织树以内、能够关联旧用户账号的职工。新旧模块分开保存，未修改旧职工记录或旧账号密码。

本次源表2311条，新增2309条，暂不处理2条：旧记录id=22与新库同工号身份存在冲突，id=1762缺少姓名/旧用户编码。异常应按旧记录id在原页面核对；不能直接覆盖已有新档案来凑齐总数。另有1条联系电话超出字段长度或格式要求，新模块留空，旧表原文保留。具体记录见 `database/legacy-roster-sync-result.json`。

| 旧字段 | 新字段 | 规则 |
|---|---|---|
| user_code | employee_no、legacy_user_code | 本次沿用旧稳定编码，关联原账号；不凭姓名合并 |
| name | employee_name | 非空才导入 |
| sex | gender | 1男、2女，其余未填写 |
| birth | birth_date | 合法出生日期，不从年龄猜测 |
| phone | phone | 有效原文；异常留空并记待核对 |
| work_unit | organization_name | 原单位显示名称 |
| v888 | team_name | 已核对旧表单，v888才是“班组”，不是department |
| exposure_history | exposure_history | 旧授权接触史原文，不生成诊断或风险分级 |
| department、insert_date | 同步审计的来源元信息 | 保留原部门及旧建档时间原文；不当作班组，不伪造旧时间的时区 |
| 无明确岗位字段 | position_name留空 | 保持待完善 |

本次同步时间作为新模块建档时间；旧建档时间另保留于审计。完整度继续按原有9项资料规则计算，不是健康评分。未导入原始体检报告、检查明细、医生结论和风险评估；在档人数增加不代表已审核或已归档。

导入根范围与来源实际单位分别保存：授权企业后台查看此档案池；小程序用户只通过自己的 `legacy_user_code` 绑定定位档案，同时验证当前旧单位仍属于档案池的组织树。账号组织迁出、存在重复本人绑定时拒绝访问，不重新建出第二份身份。后台关联旧用户也验证企业组织树，不允许跨其他企业绑定。

执行脚本 `database/sync_legacy_roster.py` 默认预检；`--apply` 才提交。数据与审计、完整度在一个事务中写入；以旧用户编码及稳定UUID防重复。已有新资料保留，不覆盖手工编辑；缺少可信身份、冲突和超出组织范围的条目会记入例外清单。重复预检新增0条。未创建新表，仍全部使用现有 `a_` 表。
