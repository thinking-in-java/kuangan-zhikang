# 数字健康师工作台

入口为「AI 数字员工中心 → AI 智能体总览」之后的第二项「数字健康师」。页面地址 `/assets/agents/health.html`，原 `/assets/digital-health/index.html` 重定向到新页面。悬浮数字人的工作台按钮使用新入口，并携带当前会话编号；后端仍按登录账号校验会话所有权。

三栏布局：左侧会话新建、搜索、删除、待确认筛选和关注；中间职工选择、对话、报告来源、查询轨迹和业务变更确认；右侧当前服务范围、重点提醒、五位数字员工实际任务状态与业务入口。关注编号保存在当前浏览器，按账号区分；对话内容沿用服务端私有存储。

数据来自现有同源接口：

| 接口 | 用途 |
| --- | --- |
| `GET /ehr/api/agent/context` | 模型启用状态、档案统计和账号能力 |
| `GET /ehr/api/agent/conversations` | 本账号会话，新增有效待确认操作数 `pendingCount` |
| `POST /ehr/api/agent/chat` | 原 Responses API 对话、工具执行与待确认变更 |
| `GET /ehr/api/agents/overview` | 今日五位员工任务、全部积压和最近动态 |
| `GET /ehr/api/agents/tasks` | 任务筛选与分页；`priority=high_or_urgent` 查询高优先和紧急任务 |

新增模型只读工具 `get_digital_worker_overview` 和 `list_digital_worker_tasks`，仅向已授权后台医生开放，复用相同范围校验。原有职工查询、报告解析、异常查询、修改与删除预览完整保留；模型无法直接执行修改、删除或审核。生成方案、随访及预警处置通过实际业务页面办理。

统计口径：顶部待审核与右侧待办是全部历史任务的当前积压；员工卡片的「今日」是北京时间当天创建的任务。任务数、风险职工人数、待确认操作数是不同口径。空数据为零；失败显示不可用；不复制原型示例数字或伪造运行状态。

验证：Java 隔离事务回归（全部回滚），真实账号读取与浏览器布局验证。浏览器中的模型传输使用明确标注的测试回复，临时会话随后删除；该验证不代表真实模型调用成功。未配置模型时页面明确显示模型待配置。
